## 关键发现 (data correctness log)

1. **生姜查不到**. 数据库 `044xxx` 系列以葱蒜为主. 我们看到 "044402 韭黄" 但无 "姜" 命名. 一些菜不放姜 (白切鸡/清蒸) 是正确的 fallback.
2. **土豆分两类**:
   - `021101` = 新鲜马铃薯 (用于青椒土豆丝/蒜蓉茄子 等)
   - `022110` = 淀粉(马铃薯) (用于勾芡非主菜用途)
3. **代表值用 `x` 后缀** = 一行覆盖一类. 推荐优先用 `x`.
4. **北方/南方差异**: 炸鸡王系列 `09130x` 已是成品菜, 用 `091104 肉鸡(肥)` 反推.
5. **蜂蜜 `076xxx` 极少** (1-2 条), 改用糖 `071xxx` 或糖浆.
6. **常见备忘**:
   - 052010 裙带菜 当作 海带丝
   - 081108 硬五花 当作 五花肉
   - 051014 木耳(水发) = 30g 水发 = 干木耳 5g (出成率 6:1)
7. **vc 大量 "Tr"** = 微量/未检出. 计算时当 None / 0.

## 单位约定

所有营养值按 **每 100g 可食部** 计. `edible_pct` 字段是该项占总重的可食部百分比. 计算实际:
```
实际营养 = Σ(原料克数 × edible_pct/100 × 营养值_per_100g / 100)
```
例: 150g 鸡腿原料, edible_pct=53, 蛋白 per_100g 接近 18g:
```
蛋白 = 150 × 0.53 × 18/100 = 14.3g (这才是 "1 份鸡腿" 的真实蛋白值)
```

## 不要做

- ❌ 用 "082220 猪肉五花" 之类的瞎猜 code (数据库里没)
- ❌ 把"鱼香肉丝"当荤菜, 实际原料无鱼, 但代码仍要走 items[] 显式
- ❌ 在 nutrition SUM 时忘记吃 edible_pct
- ❌ 假设盐在食物本底里就够 — 必须叠加 cooking adjustment

## 营养字段特殊值处理 (实测)

- **"Tr"** (trace) = 微量未检出. 营养算法中 `parse_num()` 应转为 `None`, 不进入累加; `int/None` 比较时不能放 0 (那会算错了).
- **空字符串 `""`**: 同上, 转 `None`.
- **数值字段为 NULL**: 营养数据库约 30 条 kcal 为空 (主要是"代表值以外的子分类样本"), 几十到几百条 vc/单项矿物质的 NULL. 算时不能 `float(None)` 直接报 — 必须过滤掉.

## 数据现状 (在一个 87 道菜的 MVP 中实测)

- **1657 条全部能 join `foods+nutrition` 表**, 没有断裂
- **健康菜自动判定** 命中率 48/87 = 55% (与"清蒸/水煮/炖/凉拌" 类的占比一致)
- **季节加权**: 8 月跑 4 周, "蔬菜" 主料类菜出现从基线 32 道涨到 37 道 (+15%), 季节性确实起作用
- **Tr 占 vc 总**: 1657 条里约 1000 条 vc = "Tr". 几乎是肉/鱼/蛋类的常态. 不要惊讶.
